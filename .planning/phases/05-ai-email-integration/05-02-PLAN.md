model Faq {
  id        String   @id @default(cuid())
  question  String
  answer    String   @db.Text
  tags      String[] @default([])
  createdAt DateTime @default(now()) @map("created_at") @db.Timestamptz(3)
  updatedAt DateTime @updatedAt @map("updated_at") @db.Timestamptz(3)

  @@map("faqs")
}

**system.ts** -- Modify the `buildSystemPrompt` function:

1. Add a `formatFaqs` helper:
```typescript
export function formatFaqs(faqs: Array<{ question: string; answer: string }>): string {
  if (faqs.length === 0) {
    return 'No FAQ entries available -- respond based on the general business information above.';
  }
  return faqs
    .map((f, i) => `${i + 1}. **Q:** ${f.question}\n   **A:** ${f.answer}`)
    .join('\n\n');
}
```

2. Insert a new "Frequently Asked Questions" section in the system prompt between the events/availability section and the guardrails section:
```
## Frequently Asked Questions

Use these pre-approved answers when the guest's question matches. Adapt the tone and language to the guest's context. If responding in German, translate the FAQ answer naturally.

${formatFaqs(context.faqs)}
```

Key design decisions:
- ALL FAQ entries are injected into every prompt (per user decision: "AI uses semantic relevance to pick which ones apply" -- the LLM naturally selects relevant FAQs based on conversation context)
- FAQ entries are English-only (per user decision) -- the AI translates when responding in German
- No embedding-based retrieval needed -- expected 10-50 FAQ entries fits well within token limits
- Tags are for admin UI filtering only, not for prompt selection
