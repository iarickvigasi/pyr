  <action>
    Create a new `packages/assistant/openclaw-plugin/` directory as a TypeScript package within the monorepo.

    **package.json:** Name `@pyr/openclaw-plugin`, type `module`, with dependencies: `openclaw` (latest -- provides PluginApi types for `api.registerTool()`), `@sinclair/typebox` (for JSON Schema tool parameter definitions). Scripts: `build` (tsc), `type-check` (tsc --noEmit). No test script needed -- tools are integration-tested via OpenClaw.

    **tsconfig.json:** Extend `../../tsconfig.base.json`, outDir `./dist`, rootDir `.`, ESM target.

    **openclaw.plugin.json:** Plugin manifest with id `pyr-assistant`, configSchema with `apiUrl` (string) and `apiKey` (string, sensitive).

    **lib/api-client.ts:** Create `createApiClient(baseUrl: string, apiKey: string)` factory returning an object with `get<T>(path, params?)` and `post<T>(path, body?)` methods. Uses native `fetch` with `X-API-Key` header for authentication (matching the PYR backend API key auth pattern). Parses JSON response and returns `response.data` directly (unwrapping the `{ data: T }` envelope). Throws descriptive errors on non-2xx responses. Cap all list requests to `limit=20` by default to avoid blowing up LLM context.

    **lib/formatters.ts:** Export helper functions:
    - `formatDate(iso: string): string` -- returns "15 Mar 2026" format
    - `formatDateTime(iso: string): string` -- returns "15 Mar 2026, 10:00" format
    - `formatEurCents(cents: number): string` -- returns "EUR 450.00"
    - `formatBookingStatus(status: string): string` -- human-readable status
    - `formatEventType(type: string): string` -- human-readable event type (puppy_yoga -> "Puppy Yoga Class", etc.)
    - `dashboardUrl(path: string): string` -- returns relative dashboard URL (e.g., `/guests/123`)

    **tools/guests.ts:** Export `registerGuestTools(api, client)` registering:
    - `search_guests` -- calls GET /api/v1/guests with `search` param. Returns guest name, email, phone, language, tags, dashboardUrl.
    - `get_guest` -- calls GET /api/v1/guests/:id. Returns full guest profile with booking history summary and dashboardUrl.
    - `list_guests` -- calls GET /api/v1/guests with optional `limit` param. Returns recent guests.

    **tools/bookings.ts:** Export `registerBookingTools(api, client)` registering:
    - `list_bookings` -- calls GET /api/v1/bookings with optional `status`, `from`, `to` filters. Returns bookings with guest name, room, dates, status, formatted totalPrice, dashboardUrl.
    - `get_booking` -- calls GET /api/v1/bookings/:id. Returns full booking detail with guest info, room info, dashboardUrl.

    **tools/rooms.ts:** Export `registerRoomTools(api, client)` registering:
    - `list_rooms` -- calls GET /api/v1/rooms. Returns rooms with type name, status.
    - `list_room_types` -- calls GET /api/v1/room-types. Returns room types with formatted basePrice, maxOccupancy.
    - `check_availability` -- calls GET /api/v1/availability with `from` and `to` date params. Returns available rooms for the date range.

    **tools/events.ts:** Export `registerEventTools(api, client)` registering:
    - `list_events` -- calls GET /api/v1/events with optional `from`, `to` filters. Returns events with formatted type, date/time, capacity, registered count, dashboardUrl.
    - `get_event` -- calls GET /api/v1/events/:id. Returns event detail with registrations.
    - `list_event_registrations` -- calls GET /api/v1/events/:id/registrations. Returns registered guests for a specific event.

    **tools/conversations.ts:** Export `registerConversationTools(api, client)` registering:
    - `list_conversations` -- calls GET /api/v1/conversations with optional `status` filter. Returns conversations with guest name, subject, channel, latest message preview, dashboardUrl.
    - `get_conversation` -- calls GET /api/v1/conversations/:id. Returns conversation with message thread and any AI drafts.

    **tools/dashboard.ts:** Export `registerDashboardTools(api, client)` registering:
    - `get_dashboard_stats` -- calls GET /api/v1/dashboard/stats. Returns KPIs with formatted revenue.
    - `get_today_schedule` -- calls GET /api/v1/dashboard/today. Returns today's check-ins, check-outs, events with dashboardUrls.

    **tools/settings.ts:** Export `registerSettingsTools(api, client)` registering:
    - `get_settings` -- calls GET /api/v1/settings. Returns application settings (non-sensitive subset).

    **index.ts:** Plugin entry point. Default export object with `id: "pyr-assistant"`, `name: "PYR Business Assistant"`, and `register(api)` function that:
    1. Reads config from `api.config` with `process.env` fallbacks for `PYR_API_URL` and `PYR_API_KEY`
    2. Creates API client via `createApiClient()`
    3. Calls all `registerXxxTools(api, client)` functions
    4. Logs "PYR Assistant plugin loaded: N tools registered"

    All tool `execute()` functions return `{ content: [{ type: "text", text: JSON.stringify(formattedData, null, 2) }] }` per OpenClaw plugin SDK format.

    All tool descriptions should be clear and contextual so Claude knows when to use them. Include examples in descriptions where helpful (e.g., "Search for guests by name, email, or phone number. Example: search for 'Anna' or 'anna@gmail.com'").

    Pre-format all dates, amounts, and enum values in tool responses using the formatters. Include `dashboardUrl` in every entity response so the WebChat UI can render clickable links.

    Run `pnpm install` after creating the package to resolve workspace dependencies.
  </action>
