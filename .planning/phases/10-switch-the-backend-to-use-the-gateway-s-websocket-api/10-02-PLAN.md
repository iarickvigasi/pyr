    **1. Rewrite `assistant.routes.ts` to use WebSocket chat:**

    Replace the HTTP fetch + response piping with WebSocket `chat.send` + event bridge to SSE.

    The new flow:
    a. Receive POST /chat request with `{ message, sessionKey }`.
    b. Get `app.gateway` (the GatewayWsClient singleton).
    c. Hijack the reply and write SSE headers (same as current).
    d. Subscribe to chat events via `gateway.onChatEvent(handler)` BEFORE sending the request.
    e. In the chat event handler, filter by `sessionKey` match. For each event:
       - If `state === 'delta'` and `message` exists: transform the `ChatEvent` payload into OpenAI-compatible SSE format and write to the response. The transform must produce: `data: {"choices":[{"delta":{"content":"<text>","tool_calls":<if present>}}]}\n\n`. The `message` field in ChatEvent should contain an object with `content` and optionally `tool_calls` -- extract these fields. If `message` is a string, wrap it as `{ content: message }`.
       - If `state === 'final'` or `state === 'error'` or `state === 'aborted'`: write `data: [DONE]\n\n`, end the response, and unsubscribe.
    f. Send `chat.send` RPC request via `gateway.request('chat.send', { sessionKey, message, idempotencyKey: crypto.randomUUID() })`.
    g. If gateway.request throws, unsubscribe, end the response.
    h. Import `crypto` from Node.js built-in.

    **Important SSE format preservation:** The current frontend (`use-assistant.ts`) parses `choices[0].delta.content` and `choices[0].delta.tool_calls`. The transform layer MUST produce this exact format so the frontend does not need changes.

    **Fallback for gateway not connected:** If `!app.gateway.isConnected`, return 502 immediately with `{ error: { code: 'GATEWAY_DISCONNECTED', message: 'Gateway WebSocket not connected' } }`.

    Keep the existing `/chat/reset` endpoint unchanged.

    **2. Rewrite `notification.service.ts` to use WebSocket agent method:**

    Replace `sendViaHook` with `sendViaGateway`. The new function:
    ```typescript
    export async function sendViaGateway(
      app: FastifyInstance,
      hookPath: string,
      message: string,
    ): Promise<void> {
      try {
        // Replicate the hook mapping behavior from openclaw.json:
        // - briefing: deliver=true, sessionKey=hook:briefing
        // - alert: deliver=true, sessionKey=hook:alert
        // - draft: deliver=false, sessionKey=hook:draft:<message-hash>
        const deliver = hookPath !== 'draft';
        const sessionKey = hookPath === 'draft'
          ? `hook:draft:${Date.now()}`
          : `hook:${hookPath}`;

        await app.gateway.request('agent', {
          message,
          agentId: 'main',
          sessionKey,
          deliver,
          idempotencyKey: crypto.randomUUID(),
        });
        app.log.info({ hookPath }, 'Gateway agent request sent');
      } catch (err) {
        app.log.error({ err, hookPath }, 'Gateway agent request failed');
      }
    }
    ```

    Update ALL callers of `sendViaHook` within notification.service.ts to call `sendViaGateway` instead. The callers are:
    - `processMorningBriefing` -- calls `sendViaHook(app, 'briefing', message)` -> `sendViaGateway(app, 'briefing', message)`
    - `processGuestArrivalAlert` -- calls `sendViaHook(app, 'alert', message)` -> `sendViaGateway(app, 'alert', message)`
    - `processOverdueInvoiceAlert` -- calls `sendViaHook(app, 'alert', message)` -> `sendViaGateway(app, 'alert', message)`
    - `sendNewBookingAlert` -- calls `sendViaHook(app, 'alert', message)` -> `sendViaGateway(app, 'alert', message)`
    - `sendDraftReadyNotification` -- calls `sendViaHook(app, 'alert', message)` -> `sendViaGateway(app, 'alert', message)`

    Remove the old `sendViaHook` function entirely. Also import `crypto` from Node.js built-in.

    Update `HookPayload` type in `notification.types.ts` -- this type is no longer needed since we no longer construct HTTP payloads. Remove the import and type, or keep it if other code references it (check first).

    **3. Update AI health check in `services/ai/index.ts`:**

    Replace the HTTP POST health check with a WebSocket connection check:
    ```typescript
    async healthCheck() {
      // WebSocket connection state is the health indicator
      // app.gateway is the persistent WS connection -- if connected, both primary and fallback are considered available
      // (OpenClaw Gateway handles provider failover internally)
      const connected = app.gateway?.isConnected ?? false;
      return { primary: connected, fallback: connected };
    },
    ```

    Remove the `fetch` call to `/v1/chat/completions` for health checking.

    **Important:** Best-effort delivery pattern MUST be preserved -- `sendViaGateway` catches errors and logs them but never throws, exactly like the current `sendViaHook`.
